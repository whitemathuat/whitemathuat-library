# DECISIONS

Rules in force (short summary) + numbered decisions below, max ~5 lines each. When this file grows long, move old full entries to `docs/archive/` and keep their numbers.

## Rules in force (as found in the code)
- Static site generated by JavaScript scripts in `tools/` (Node, no npm libraries): edit `templates/`, `css/`, `tools/`, then rebuild; generated `index.html` files are committed (1, 4).
- Change order for UI work: CSS first, then template, then generator script (README_PROJECT.md / PROJECT_STRUCTURE.md) (1).
- Book data: one folder per book in `novels/`, notes from the Kindle export, review in `review.md` (1).
- Online behind a browser login (`USERNAME` / `PASSWORD` Cloudflare variables) (1); if either variable is missing the site stays locked (503); `npm run check` tests the gate (9).
- Every push to GitHub `main` goes live automatically; tag `online` = live commit (2).
- Daily work on branch `dev`; `main` changes only through `/len-mang` (3).
- Look: design 2a (sky blue-violet, pink clouds, navy + cream paper cards); colours only in `css/theme.css`, fonts stored locally in `fonts/` (5).
- Covers: `cover.jpg` at most 600 px wide / 300 KB; `npm run covers` shrinks them (8).
- Books can be saved from the website: `functions/api/save-book.js` commits to GitHub (`main` from the live site, `dev` from the dev preview) with the `GITHUB_TOKEN` Cloudflare secret; the GitHub Action `build-books.yml` then parses, builds, checks and commits the pages. Website saves go live without `/len-mang`; pull `main` into `dev` before working (11).

Invisible trailing spaces at line ends were dropped from the pages, nothing else changed. Finished 2026-11-24: all Python removed; the Kindle reader needs no library (the export is regular `<div class>` blocks).

11. **Add/edit books from the website, step 1 = backend (2026-11-25, user OK'd a 3-step plan).** Steps: 1 save function + auto-build, 2 "Thêm sách" page, 3 cover crop (drag/zoom like a profile photo) + links, rating, review, editing existing books. Build runs in a GitHub Action (not a Cloudflare build command) so the repo always holds the finished pages and no Cloudflare setting changes. Function rules: JSON only + same origin (blocks other sites posting with the cached login), slug `a-z0-9-`, cover JPEG ≤ 300 KB, notebook must be a Kindle export, `review.md` built on the server with today's `date:`. 12. **"Thêm sách" page = step 2 (2026-11-26, user asked).** `books/add.html` (built by `tools/build_add.js`, browser code `js/add-book.js`): pick the Kindle file + a cover, preview title/author/chapters, save via `/api/save-book`. The Kindle reader moved to `js/notebook.js` so the page and `npm run parse` use the same code. A cover is required (check.js needs `cover.jpg`); the browser shrinks it to 600 px JPEG ≤ 300 KB (crop comes in step 3). An empty review is sent so `review.md` gets today's date and the book sorts first. Same folder name or same title as an existing book is blocked (editing = step 3). Only works online (local file:// shows a note). Tests: `tools/check_add.js`.
